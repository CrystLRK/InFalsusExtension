# Native ABI 兼容配置

Mod 入口固定读取：

```text
InFalsusChartExt/native-profiles.json
```

入口按 `GameAssembly.dll` 与 `global-metadata.dat` 的 SHA256 选择 profile。
当前 schema 版本为 `2`；未知或旧版 schema 会 fail-closed。
profile 子文件名可由 `file` 字段自定义，但必须位于入口文件目录内。

单个 profile 包含：

- 所有 native 字段 offset、类型大小和 stride；
- `Presentation` 元组布局和 Queue.Enqueue 参数尺寸；
- 容量补丁的 opcode、扫描范围、模式间隔和站点数量；
- 所有 Harmony/native 入口的 assembly、namespace、class、method、
  参数签名、返回类型、RVA、fallback RVA、prologue 和可选的
  `fallbackPrologue`；
- 可选的 `managedMetadataToken`，用于在 managed 程序集中精确选择
  MethodInfo，随后仍校验方法名、签名、声明类型以及原生 RVA/prologue；
- 容量补丁 original value 与目标类型；
- 当前构建启用的功能能力位。

如果入口缺失、hash 不匹配、JSON 损坏或任一关键字段缺失，Mod 会禁用全部
native-write 功能；不会猜测 offset，也不会尝试部分写入。单个可选 target
失败时只禁用依赖该 target 的能力。

Harmony target 只依赖严格 managed signature 和 class 身份；native hook
target 才校验原生入口。泛型 native target 会在运行时先膨胀为 profile
声明的封闭类型，再比较主/fallback RVA 和对应 prologue。存在 fallback
RVA 时建议同时提供 `fallbackPrologue`；缺少时 fallback 无法通过严格入口
校验。

升级游戏时优先使用：

```text
internal-docs/tools/generate_native_profile.py
```

从 GameAssembly、metadata、`dump.cs` 和 `script.json` 生成候选 profile。
工具不会自动把候选标记为可信，字段布局仍需对照 dump 人工复核。

只有 profile 无法表达的签名、调用顺序、所有权或生命周期变化，才需要修改
业务代码。

`managedMetadataToken` 不是跨版本固定值，而是当前 MelonLoader/Cpp2IL
生成程序集内的 MethodDef token。升级后 token 改变通常只需更新 profile：

- current `Track.Update`：`0x06003885`；
- latest `Track.Update`：`0x0600395F`。

如果 token 无法解析或解析结果与签名、RVA/prologue 不符，依赖该 target
的能力必须整体关闭，禁止回退到其他同名方法。

容量补丁的三个构造器入口同样属于严格 target：

- `capacityChartConstructor`：`_b._T..ctor()`；
- `capacitySideNoteConstructor`：`_b._hA..ctor()`；
- `capacityJudgeConstructor`：`_E._VD..ctor(DataAccess, _sD)`。

独立 SkyArea 的原生反馈事件入口：

- `gameSceneEventDispatch`：`GameScene._Mk(_Uh, _Sh)`，由
  `SkyFeedback` 能力位控制。

Mod 只在 block 首个 `EXACT+` 后构造 event type 6，并在该 block
“已成功、当前覆盖、无 penalty”时构造 event type 5(true)，条件失效时
构造 event type 5(false)。事件随后交给原版 `_Mk`。音频节流、音量、voice
和共享音轨均由原版处理；普通 SkyArea 不接收 Mod event 5；Mod 不直接调用
`_xk`/`_zk`。

升级后只要 managed 参数签名、RVA 和 prologue 可按同一 schema 表达，通常
只需重新生成 profile；参数语义、调用顺序或容量分配逻辑变化仍需要代码适配。
